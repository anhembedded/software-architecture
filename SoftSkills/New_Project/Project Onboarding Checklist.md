# ☑️ Project Onboarding Checklist

> [!abstract] TL;DR
> Use this on day one. You don't need to finish it in a day; use it to decide your **next step**.

Index: [[Thinking New project]] · Mapping: [[PMBOK Mapping]]

---

## 🧩 Understand the problem — *Initiating / Scope*
→ [[01 Clarify]]

- [ ] I can state the project goal in my own words.
- [ ] I know the scope and which parts are my responsibility.
- [ ] I know the acceptance criteria, or the points that need confirmation.
- [ ] I have written down the open questions.

## 🗺️ Understand the system — *Planning (EEF / OPA)*
→ [[02 Discover]]

- [ ] I found the repository, documentation and key contacts.
- [ ] I know how to build, run and test the baseline.
- [ ] I identified the entry point and the related modules.
- [ ] I traced at least one important data or processing flow.

## 🛡️ Reduce risk — *Risk Management*
→ [[03 De-risk]] · [[Risk Register]] · [[Technical Spike Template]]

- [ ] I listed the key technical assumptions.
- [ ] I ranked the high-impact risks.
- [ ] I know which spike is needed to verify feasibility.
- [ ] I checked the key dependencies and blockers.

## 📋 Plan and communicate — *Schedule / Communications*
→ [[04 Plan]] · [[09 Communication]]

- [ ] I have a first milestone with a clear deliverable.
- [ ] I know which dependencies need support from other teams.
- [ ] I know when and how I will report progress.
- [ ] I have not committed to a deadline beyond what the evidence supports.
